## 1. 仮説

**仮説H**: unknownを明示管理し、Thought Traceを記憶として残し、Orchestratorで制御する
アーキテクチャ（C4）は、最良ベースライン（B0/B1/B2 の中で最も成功率が高い条件）より
評価成功率（overall >= 0.70 の割合）を意味のある差で向上させる。

## 2. 条件

| 条件 | 説明 | 本Stepでの実装 |
|---|---|---|
| B0 | 単純な指示、Memoryなし | ✅ 実装済み |
| B1 | Reflexion（失敗後に振り返り改善） | ✅ 本Stepで実装 |
| B2 | Self-Refine（生成内 feedback→improve 反復） | ✅ 本Stepで実装 |
| C4 | Insight Synapse 全成分（unknown + 探索ループ + Thought Trace + Orchestrator） | ✅ 実装済み（Step 2 で較正） |

**比較相手**: 4条件すべてを実行し、**最良ベースライン**（B0/B1/B2 の最高成功率）を
C4 の比較相手とする。実行前に最良ベースラインを固定しない（探索的選択は
しない。観測後、機械的に最高値を採用する）。

## 3. 試行数・タスク

- タスク: `poc/tasks.py` の本番セット20問（AIサービス企画ドメイン、Step 1 と同一）
- 各タスクは全条件に同じ問題を出題（タスク×条件の交絡を排除）
- 実行順はシード42でシャッフル（カウンターバランス。ハーネス `poc/harness.py` が実施）

## 4. 効果量の定義（事前登録）

- **成功率**: overall >= 0.70 の試行の割合（03/00 §2.4 の合格判定）
- **効果量**: C4成功率 − 最良ベースライン成功率 の**絶対差（pp）**
- 効果量の95%信頼区間: Newcombeのハイブリッドスコア区間（`poc/stats.py`）
- **棄権率**: 各条件の棄権試行割合を成功率と併記する（03/00 §3.5）

## 5. 判定帯域（11/09 §12・03/00 §8.2）— 実行前に固定

```text
効果量（最良ベースライン比の絶対差）と判定：

  < 5pp または低下 → 仮説Hは棄却
  5〜20pp           → 判定不能帯域（測定誤差に埋もれる可能性）→ 追試必須
  20〜39pp          → 未確定帯域（N=20の検出力では決定的支持を出せない）→ 追試必須
  >= 39pp           → 決定的支持（N=20で80%検出力の範囲内）
```

判定帯域は Step 1 と同一（§12・§13 を踏襲）。較正は測定器の調整であり、
判定基準の変更ではない。

## 6. 追試ルール（11/09 §12）— 事前登録

5〜39pp のいずれかの帯域に落ちた場合、Step 1 と同じ §6 を踏襲する：

```text
1. まず効果量の95%信頼区間を計算する
2a. 信頼区間の下限が5pp未満の場合 → 効果は「統計的に区別できない」と判定（支持保留）
2b. 信頼区間全体が5pp以上にある場合 → 効果は存在するがサイズが小さいと判定（支持的証拠）
3. いずれの場合も、Nを増やした追試（N=74/群以上）を事前登録通り実施し、
   その結果で支持 / 棄却を確定させる
4. 追試の結果のみをもって最終判定とし、帯域観測単独では仮説Hを支持しない
```

### 追試ループの停止条件（無限再帰の封印）

```text
- 追試は最大1回（初回 + 追試1回の計2回で打ち切り。3回目は実施しない）
- 追試N = 74/群以上（20ppを80%の検出力で確定できる最小N、§14）
- 追試の結果が < 5pp   → 棄却を確定（効果なし）
- 追試の結果が >= 20pp → 決定的支持を確定
- 追試の結果が 5〜20pp → 支持保留（未実証）として最終判定し、実験を終了
```

## 10. 測定系の較正内容とその正当化

Step 2 で変更したのは**測定系**（棄権機構・探索プロセス・評価ルーブリック）であり、
仮説H に有利になるように判定基準を動かすものではない。各変更の正当化を記す。

### 10.1 棄権閾値の再設定（unknown_level≥0.7 → ≥0.85 / confidence<0.3 → <0.15）

- **観測**: Step 1 の C4 全20試行で unknown_level が 0.738〜0.922 に分布し、
  閾値 0.7 で 100% 棄権となった
- **問題**: 閾値はタスクドメインの「本質的不確実性」に依存する。AIサービス企画
  ドメインでは初期 unknown_level が系統的に高く、閾値 0.7 は探索開始を
  ほとんど許さない
- **較正**: unknown_level≥0.85 / confidence<0.15 に再設定。Step 1 データでは
  約30%が棄権・70%が探索となり、棄権を適切な割合に抑える

### 10.2 探索ループの実装（従来: 付加指示で1回生成のみ）

- **問題**: 従来は decision=="explore" でも unknown を実際に減らす手段がなく、
  探索判定が事実上の「低品質生成」になっていた
- **較正**: 重要度の高い unknown を構造分析で解決し State に反映する反復ループ
  （最大5反復・1回3項目）を実装。unknown が減り confidence が上がることで
  create 判定に到達できる
- **探索成果の生成反映**: 探索で得た認知状態（既知・未知・作業仮説）を
  成果物生成プロンプトに必ず渡す（`_build_analysis_context`）。各 `generate()`
  呼び出しはステートレスのため、反映しないと探索の成果が最終成果物に
  一切現れず、C4 が B0 と実質同一の出力になる（対照実験として不成立）。

### 10.3 ルーブリックの改訂（Risk 軸の再定義・Quality/Value に誠実さ基準）

- **観測**: Step 1 で C4 の abstain 出力はリスクを明示的に列挙するため Risk スコアが
  系統的に高くなり、(1−Risk) の逆転で overall が低下した
- **問題**: Risk 軸が「提案そのもののリスク」と「分析がリスクを正直に開示していること」を
  混同。正直な分析ほど低評価になる構造的バイアス
- **較正**: Risk 軸を「リスク認識と対策の適切さ」に再定義。Quality に
  「不確実性を適切に区別」、Value に「条件付き価値の現実性」を追加。
  **改訂後も overall 計算式（Q×0.25+L×0.20+C×0.20+V×0.25+(1−R)×0.10）は不変**

### 10.4 「較正が有利化でない」ことの確認

- 判定帯域（§5）・追試ルール（§6）・解析計画（§7）は Step 1 と同一
- ルーブリック改訂は B0/B1/B2/C4 の**全条件に同一適用**（特定条件に有利でない）
- 棄権閾値の緩和は「abstain 出力を減らして成功率を上げる」方向だが、
  棄権は C4 のみの機構であり、C4 の成功率を上げる方向の較正ではない
  （abstain 出力は評価対象になり、むしろ低評価を引きやすい）。測定器が
  C4 の出力特性を公正に測れるようにするための調整である

## 11. 実装の前提（崩れた出力の扱い）

wisdom-council-layer の運用規約（`CLAUDE.md`「崩れたら再生成」）に準拠する。

- known/unknown列挙・探索ステップ・評価スコア等の出力がパースできない場合、
  **手で直さず再生成**する（`poc/conditions.py` / `evaluation/evaluator.py` が
  明確なエラーで検出）
- 形式エラー時は**エラー内容をフィードバックして最大3回再生成**する
  （自動リトライ。再生成は新しいモデル呼び出しであり、出力の手編集ではない）
- 3回後も失敗する試行は**「失敗」として明示的に記録**し、除外はしない
  （サイレントドロップ禁止）
