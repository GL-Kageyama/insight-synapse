## 1. 仮説

**仮説H**: unknownを明示管理し、Thought Traceを記憶として残し、Orchestratorで制御する
アーキテクチャ（C4）は、最良ベースラインより評価成功率（overall >= 0.70 の割合）を
意味のある差で向上させる。

本Stepは**対照実験**であり、成分別の効果帰属（C1-C3）は含まない。

## 4. 効果量の定義（事前登録）

- **成功率**: overall >= 0.70 の試行の割合（03/00 §2.4 の合格判定）
- **効果量**: C4成功率 − 最良ベースライン成功率（本Stepでは B0）の**絶対差（pp）**
- 効果量の95%信頼区間: Newcombeのハイブリッドスコア区間（`poc/stats.py`）

## 5. 判定帯域（11/09 §12・03/00 §8.2）— 実行前に固定

```text
効果量（最良ベースライン比の絶対差）と判定：

  < 5pp または低下 → 仮説Hは棄却
  5〜20pp           → 判定不能帯域（測定誤差に埋もれる可能性）→ 追試必須
  20〜39pp          → 未確定帯域（N=20の検出力では決定的支持を出せない）→ 追試必須
  >= 39pp           → 決定的支持（N=20で80%検出力の範囲内）
```

## 6. 追試ルール（11/09 §12）— 事前登録

5〜39pp のいずれかの帯域に落ちた場合：

```text
1. まず効果量の95%信頼区間を計算する
2a. 信頼区間の下限が5pp未満の場合 → 効果は「統計的に区別できない」と判定（支持保留）
2b. 信頼区間全体が5pp以上にある場合 → 効果は存在するがサイズが小さいと判定（支持的証拠）
3. いずれの場合も、Nを増やした追試（N=74/群以上）を事前登録通り実施し、
   その結果で支持 / 棄却を確定させる
4. 追試の結果のみをもって最終判定とし、帯域観測単独では仮説Hを支持しない
```

### 追試ループの停止条件（無限再帰の封印）

```text
- 追試は最大1回（初回 + 追試1回の計2回で打ち切り。3回目は実施しない）
- 追試N = 74/群以上（20ppを80%の検出力で確定できる最小N、§14）
- 追試の結果が < 5pp   → 棄却を確定（効果なし）
- 追試の結果が >= 20pp → 決定的支持を確定
- 追試の結果が 5〜20pp → 支持保留（未実証）として最終判定し、実験を終了
```

## 7. 解析計画（事前登録）

1. 条件別成功率を Wilsonスコア区間（95%）で推定
2. 効果量（pp差）を Newcombe法の95%CI で推定
3. §5の判定帯域を適用して判定
4. 帯域に落ちた場合のみ §6の追試ルールに進む

事前登録外の検定（p値・事後検定・サブグループ分析）は探索的分析として明示し、
判定には用いない。

## 8. 報告義務（11/09 §14）

すべての条件（本Stepでは B0, C4）について以下を報告する。

```text
✓ 成功率（overall >= 0.70 の割合）
✓ 効果量（最良ベースライン比の絶対差, pp）
✓ 95%信頼区間
✓ 使用LLM・温度・最大試行数（ハイパーパラメータの全条件共通化の証明）
✓ 評価者の独立性対策（盲検化の実施・独立評価系統・人間較正サンプルの一致度）
```

## 9. 評価者の独立性（事前登録）

1. **盲検化**: 評価器には条件ラベルを渡さない。評価プロンプトに B0/B1/B2/C4 等の
   条件情報を含めない（`tests/test_evaluator.py` で検証済み）
2. **独立評価系統**: 生成系（claude-sonnet-4-5）と評価系（claude-haiku-4-5）を
   別モデル系統にする。同一系統は循環評価のため禁止
   （`adapters/claude_client.py` が系統分離を強制）
3. **人間較正サンプル**: 50サンプル・ρ >= 0.70 は **Step 2 で実施**。
   本Stepの成功率は**較正なしの暫定指標**として報告し、較正未実施を明記する
4. 温度は全条件共通で 0.0（交絡の排除）

## 10. 実装の前提（崩れた出力の扱い）

wisdom-council-layer の運用規約（`CLAUDE.md`「崩れたら再生成」）に準拠する。

- known/unknown列挙・評価スコア等の出力がパースできない場合、**手で直さず
  再生成**する（`poc/conditions.py` / `evaluation/evaluator.py` が明確なエラーで検出）
- 形式エラー時は**エラー内容をフィードバックして最大3回再生成**する
  （自動リトライ。再生成は新しいモデル呼び出しであり、出力の手編集ではない）
- 3回後も失敗する試行は**「失敗」として明示的に記録**し、除外はしない
  （サイレントドロップ禁止）
