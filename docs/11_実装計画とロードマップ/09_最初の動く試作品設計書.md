# 1. 目的

本ドキュメントは、Insight Synapseの最初のProof of Concept（POC）を定義する。

目的：

> 最小構成で「判断・評価・Memory化」というInsight Synapseの核となる循環が成立することを検証し、その**実証結果**をプロジェクトの第一の成果物として提出する。

## 位置づけ（第一成果物の切り替え）

設計文書群は既に十分に熟している。**本POCは、文書から実証へのピボットである。** 本POC以降、第一の成果物は「設計文書」ではなく「実証結果」である。

```text
仮説Hが支持されるか棄却されるかを、反証可能な実験として実測し、そのレポートを提出すること自体が成果物である。
```

言い換えれば、本POCの唯一の目的は「設計の価値」を「実証の価値」へ切り替えることにある。文書の推敲は、実証結果が出た後に改めて行う。**次の修正は文書ではなく、Step1対照実験（§14）の実行結果である。**

### v0.5の位置づけ（移行文書）

本v0.5改訂は、上記の「次の修正は文書ではない」という宣言と矛盾しない。本改訂が追加する内容——構成概念妥当性の運用定義（`03_コアコンポーネント/00_数値定義書.md` §2.6.1）・支払い意思検証（§15bis）——は、いずれも「書くこと」ではなく**「測ること」の前提整備**である。これらはPOCを実行する前に、測定の妥当性と市場の実在性を確保するための最小限の計測設計であり、文書のための文書ではない。

```text
v0.4：「書くことを止め、測ることに移れ」という宣言
v0.5：測るための前提整備——何を測るか・誰が払うか・前提を疑うか・誰のために作るか
v0.6：POC実証結果レポート——実測値と判定の報告
```

v0.5は設計側の最終改訂である。v0.6以降の第一成果物は、実証データである。

# 12. 検証する仮説（反証可能・成分別分解）

本POCは、「知的循環が思考能力を改善する」という中心主張を、**効果の帰属が特定できる複数の反証可能な仮説**として切り出す。

単一の「Memoryあり vs Memoryなし」比較では、向上の原因がunknown管理なのかThought Traceなのかオーケストレーションなのかが特定できない。そこで仮説Hを**3つの成分**に分解する。

## 仮説H（全体）

```text
unknownを明示管理し、Thought Traceを記憶として残し、Orchestratorで制御するアーキテクチャは、
同一のアイデア評価タスク群において、
強力な既存ベースライン（Reflexion / Self-Refine）より評価の成功率を20%以上向上させる。
```

### 効果量の操作定義

仮説Hの効果量は、**成功率の絶対差（percentage point, pp）** として操作的に定義する。

```text
効果量 = 処理条件の成功率（overall ≥ 0.70 のタスク割合） − 比較対象ベースラインの成功率

比較対象 = B0 / B1 / B2 のうち最良（成功率が最も高い条件）とする
```

- 効果量の定義域は −100〜+100 pp
- 「20%以上向上」は「**最良ベースライン比 +20pp以上**」と解釈する（相対比ではなく絶対差）
- 成功率は `03_コアコンポーネント/00_数値定義書.md` の同一5軸ルーブリックで計測する

> この操作定義により、判定の曖昧さ（20%が相対か絶対か）を除去する。統計パラメータの正版は `03_コアコンポーネント/00_数値定義書.md` §8、検出力の根拠は §14 を参照。

## 成分仮説

仮説Hは以下の3成分に分解され、それぞれ独立に反証可能である。

### H1（unknown管理成分）

```text
unknown（未知項目）の明示管理だけを追加した場合、ベースラインより成功率が向上する。
```

> **H1の操作定義（反証可能性の担保）**：H1の実験操作は「① 未知項目の明示リスト化（unknown_list）」と「② 棄権機構のON/OFF」として機械的に定義する。ON条件では `unknown_level ≥ 0.7` または `confidence < 0.3` のときに判断を保留（棄権）して調査行動を優先し、OFF条件では保留せず現状の情報で判断を下す。棄権率（判断を保留したタスクの割合）を成功率と併記し、H1の支持は「棄権率を上回る成功率向上」でのみ判定する。棄権機構の数値定義（0.7 / 0.3）は `03_コアコンポーネント/00_数値定義書.md` §3.5 を正版とする。

### H2（Thought Trace成分）

```text
Thought Traceを記憶として残し、次の試行で参照するだけを追加した場合、ベースラインより成功率が向上する。
```

### H3（オーケストレーション成分）

```text
Orchestratorによる「探索 vs 制作」の分離制御だけを追加した場合、ベースラインより成功率が向上する。
```

## 反証条件

以下の観測が起きた場合、仮説H（または該当する成分仮説）は**棄却**される。

- 対象条件の成功率が最良ベースラインを下回る（効果量 < 0 pp）
- または向上幅が5pp未満（測定誤差の範囲内とみなす）

仮説Hが棄却された場合は、テーゼ（思考管理が能力を改善する）そのものを再設計する。
成分仮説のみが棄却された場合は、その成分の設計を再検討する（テーゼ全体は維持）。

### 判定帯域の事前登録ルール（5〜20pp / 20〜39pp）

N=20/群は約39ppの大効果しか80%の検出力で検出できない（§14）。そのため、判定帯域はN=20の検出力に整合させて定義する。判定を曖昧にしないため、**すべての帯域と追試ルールを実験前に登録する**。

```text
効果量（最良ベースライン比の絶対差）と判定：

  < 5pp または低下 → 仮説Hは棄却
  5〜20pp           → 判定不能帯域（測定誤差に埋もれる可能性）→ 追試必須
  20〜39pp          → 未確定帯域（N=20の検出力では決定的支持を出せない）→ 追試必須
  ≥ 39pp            → 決定的支持（N=20で80%検出力の範囲内）
```

5〜39pp のいずれかの帯域に落ちた場合の追試ルール（事前登録）：

```text
事前登録ルール（追試の取り扱い）：

  1. まず効果量の95%信頼区間を計算する
  2a. 信頼区間の下限が5pp未満の場合 → 効果は「統計的に区別できない」と判定（支持保留）
  2b. 信頼区間全体が5pp以上にある場合 → 効果は存在するがサイズが小さいと判定（支持的証拠）
  3. いずれの場合も、Nを増やした追試（§14の検出力分析に基づく N=74/群 以上）を
     事前登録通り実施し、その結果で支持 / 棄却を確定させる
  4. 追試の結果のみをもって最終判定とし、帯域観測単独では仮説Hを支持しない
```

追試ループの停止条件（実験が「決して決着しない」リスクを封印する）：

```text
停止条件：
  - 追試は最大1回（初回 + 追試1回の計2回で打ち切り。3回目は実施しない）
  - 追試N = 74/群以上（20ppを80%の検出力で確定できる最小N、§14）
  - 追試の結果が < 5pp   → 棄却を確定（効果なし）
  - 追試の結果が ≥ 20pp  → 決定的支持を確定（N=74の検出力で20ppを確定）
  - 追試の結果が 5〜20pp → 支持保留（未実証）として最終判定し、実験を終了
```

このルールにより、「20%向上」という野心的目標を保ったまま、判定の曖昧さを排除し、追試が無限に続くことを防ぐ。
閾値の一本化ではなく帯域ルールを採用するのは、効果量の大小を事前に断定せず、実測と追試で確定させるためである。

# 13. 対照実験の設計

## 実験方法

同一の評価タスク集合を、ベースライン条件と処理条件で実行する。

### ベースライン条件（差異化の比較対象）

```text
条件B0：ベースライン（単純な指示のみ・Memoryなし）

条件B1：Reflexion（失敗後に言語で振り返り、次の試行を改善）

条件B2：Self-Refine（同一生成内で feedback→improve を反復）
```

> ベースラインは「Memoryなし」だけではない。差異化は「主張」ではなく「実測」で示すため、
> 強力な既存自己改善手法（Reflexion / Self-Refine）との直接比較を必須とする。

### 処理条件（Insight Synapse）

```text
条件C：Insight Synapse（unknown管理 + Thought Trace参照 + Orchestrator制御）
```

- タスク数：各条件 N = 20（固定）
- タスク順は条件間で交互に入れ替える（順序効果を排除）
- 評価は同一の5軸ルーブリック（`03_コアコンポーネント/00_数値定義書.md`）を使用
- 使用LLM・温度・最大試行数等のハイパーパラメータは全条件で共通化する（交絡の排除）

## 要因実験（成分別の効果帰属）

成分別の効果を帰属するため、3つの成分（unknown管理 / Thought Trace / オーケストレーション）をON/OFFした直交実験を実施する。実用的な4条件に絞る。

| 条件 | unknown管理 | Thought Trace | オーケストレーション | 検証する成分仮説 |
|:---:|:---:|:---:|:---:|:---|
| C1 | ON | OFF | OFF | H1 |
| C2 | OFF | ON | OFF | H2 |
| C3 | OFF | OFF | ON | H3 |
| C4 | ON | ON | ON | H（全体） |

- 各条件 N = 20。要因実験 80タスク + ベースライン 3条件 60タスク = **総計140タスク**
- 効果の帰属：C1〜C4の差から各成分の寄与を分解する（分散分析）
- 20%向上の主張は、**どの成分がどれだけ効いたか**を分解して報告する（scientific-noveltyの指摘への回答）

## 測定指標

```text
1. 成功率
   評価overall ≥ 0.70 となったタスクの割合

2. 評価分散
   同一入力を2回評価した際のスコアのばらつき

3. 判断理由の質
   判断理由に根拠・代替案・リスクが含まれる割合
```

## 評価者の独立性（自己評価の循環の遮断）

成功判定を同系列AIの自己評価だけに委ねると、処理条件の成果物を処理条件自身が採点する**循環**が生じる。この循環を断つため、以下の3点をPOCプロトコルに義務付ける。

```text
1. 評価者の盲検化
   評価者は成果物がどの条件（B0 / B1 / B2 / C1〜C4）に属するかを知らされない
   状態で採点する。条件ラベルは成果物から分離して管理する。

2. 独立評価系統の併用
   処理条件の生成・判断を担うモデル系統とは独立した、別系統の評価モデルを
   評価者として用いる。処理条件と同一系統の自己評価だけで採点しない。

3. 人間較正サンプル
   人間が採点した較正サンプル（既定: 50件、`03_コアコンポーネント/00_数値定義書.md` §2.6）
   を事前に用意し、評価モデルのスコアを較正する。較正サンプル上での人間評価との
   一致度（スピアマン相関・加重κ係数）を報告する。一致度の報告がない限り、
   成功率を主要評価指標として用いない。
```

> 較正サンプルの運用定義（サンプル構造・層別設計・人間評価者プロトコル・較正手順・構成概念妥当性枠組み）は `03_コアコンポーネント/00_数値定義書.md` §2.6.1 を正版とする。成功率・unknown_level・confidence は、本定義の較正と妥当性検証を経ない限り、主要指標として用いない。

## 判定基準

| 観測結果（最良ベースライン比の絶対差） | 判定 |
|:---|:---|
| 向上幅 ≥ 39 pp | **決定的支持**。N=20の検出力（§14）で検出可能な範囲。テーゼの実証とみなす |
| 向上幅 20〜39 pp（未確定帯域） | N=20の検出力では決定的支持を出せない。§12の**事前登録ルールに従い追試を実施**し、その結果で支持 / 棄却を確定 |
| 向上幅 5〜20 pp（判定不能帯域） | 効果の存在は支持の余地があるが、§12の**事前登録ルールに従い追試を実施**し、その結果で支持 / 棄却を確定 |
| 向上幅 < 5 pp または低下 | 仮説Hは棄却。テーゼを再検討 |

成分仮説の判定は各条件（C1〜C4）に同じ基準を適用する。すべての観測結果は、効果量（pp）と95%信頼区間を併記して報告する。

# 14. 検出力分析（N=20の根拠）

## 目的

N=20/群が何を検出でき、何を検出できないかを**実験前に数値で示す**。これにより、「N=20」という規模を事後的な言い訳ではなく、事前登録された検出力の範囲として位置づける。

## 検定方式と前提

```text
検定　　　：二群比率差検定（両群の成功率を比較）
帰無仮説　：処理条件と最良ベースラインの成功率が等しい（効果量 = 0 pp）
対立仮説　：処理条件の成功率が高い（one-sided）
有意水準　：α = 0.05（片側）
目標検出力：1 − β = 0.80
```

統計パラメータ（α / β / 効果量定義）の正版は `03_コアコンポーネント/00_数値定義書.md` §8。

## 検出力計算

二群比率差検定の検出力は、平均成功率 `p̄` と効果量 `δ` に対して次式で近似する。

```text
n = (z_{1−α} + z_{1−β})² × 2 × p̄ × (1 − p̄) / δ²
```

### N=20/群で検出可能な効果量

`n = 20`、`α = 0.05`（片側 `z_{0.95} = 1.645`）、`β = 0.20`（`z_{0.80} = 0.842`）を代入し、平均成功率 `p̄ = 0.50` と仮定すると、

```text
20 = (1.645 + 0.842)² × 2 × 0.50 × 0.50 / δ²
   → δ ≈ 0.39（約39pp）
```

すなわち、**N=20/群は 80% の検出力で約39ppの大効果を検出できる**。20pp前後の効果は検出できても検出力は低く、5pp前後の効果は検出できない。**N=20は pilot 規模である。**

### 対照実験の実効検出力

判定の中心は条件C（N=20）と最良ベースライン（B0/B1/B2）の比較である。最良ベースラインの推定を安定させるため、ベースライン3条件（各N=20）は解析時に**プールした成功率**を比較対象に用いる。

```text
比較：C4（N=20）vs プール済みベースライン（N=60）
     → 検出力は「20 vs 60」の不均等な二群比較として評価する
     → 単純な20 vs 20より検出力が高い
```

プール済みベースライン（N=60）を比較対象とした場合、実効検出力は上記の等群近似より高くなる。実測値は効果量とともに95%信頼区間（Wilson / Agresti-Coull法）で報告する。

## N=20の位置づけと追試計画

```text
N=20/群 = pilot規模（大効果の検出を目的とする）
  ・約39ppの大効果 → 高い検出力で検出可能（決定的支持の下限）
  ・20pp前後の効果 → 検出の可能性はあるが検出力は限定的（未確定帯域）
  ・5pp未満 → 検出不能（= 反証条件に相当）

→ 判定帯域（5〜39pp）に落ちた場合の追試N（§12の事前登録ルール）：
   追試の目的を「20pp前後の効果を80%の検出力で確定する」とし、
   δ = 0.20、p̄ = 0.60（ベースライン0.50と処理0.70の平均）を代入すると、
   n = (1.645 + 0.842)² × 2 × 0.60 × 0.40 / 0.20² ≈ 74 / 群
   → N=74/群 以上で20pp前後の効果を80%の検出力で確定できる
```

追試N=74/群は、帯域観測時の**事前登録された最小N**であり、これ以上のN増も認める。

## 追試ループの停止条件

追試が「決して決着しない」リスクを封印するため、追試には以下の停止条件を事前登録する。

```text
追試ループの停止条件：
  1. 追試は最大1回（初回 + 追試1回の計2回で打ち切り。3回目は実施しない）
  2. 追試N = 74/群以上（20ppを80%の検出力で確定できる最小N）
  3. 追試結果 < 5pp   → 棄却を確定（効果なし）
  4. 追試結果 ≥ 20pp  → 決定的支持を確定（N=74の検出力で20ppを確定）
  5. 追試結果 5〜20pp → 支持保留（未実証）として最終判定し、実験を終了
```

追試結果は必ず最終判定（棄却 / 決定的支持 / 支持保留）のいずれかに到達する。効果の有無が不明のまま実験が続き続けることはない。

## 報告義務

すべての条件（B0〜B2, C1〜C4）について、以下を報告する。

```text
✓ 成功率（overall ≥ 0.70 の割合）
✓ 効果量（最良ベースライン比の絶対差, pp）
✓ 95%信頼区間
✓ 使用LLM・温度・最大試行数（ハイパーパラメータの全条件共通化の証明）
✓ 評価者の独立性対策（盲検化の実施・独立評価系統・人間較正サンプルの一致度）
```

これは「反証可能性の誠実さ」を維持するための最低限の報告である。

# 15bis. 支払い意思の実証（POC実行の前提条件）

本POCの成功は「成功率の統計的有意差」だけでは定義されない。設計仕様書群へのWisdom Council評価（v0.4-full）が指摘した通り、3セグメントの列挙（`01_コンセプトと哲学/01` §11）は需要の存在を示さない。以下の支払い意思検証を、POC実行の前提条件として組み込む。

## 事前：顧客発見インタビュー（Pre-POC）

POCのStep 1対照実験に着手する前に、3セグメントの想定採用者に対して**10〜15件**の顧客発見インタビューを実施する。

```text
インタビュー対象（各セグメント3〜5名）：
  セグメント1：AI評価・観測性ベンダーのプロダクト責任者
  セグメント2：オープンソースLLMトレースツールのメンテナ
  セグメント3：企業AIガバナンス・監査チームの責任者

インタビュー構造（半構造化）：
  1. 現在のAI評価・監査の課題（何に困っているか）
  2. Thought Traceフォーマットへの関心（何が解決されるか）
  3. 支払い意思額（この課題に年間いくら割くか、現在の予算規模）
  4. 購買決定者（誰が予算を承認するか）
```

顧客発見インタビューは「書く」ではなく「測る」の一部である——仮説（3セグメントに需要がある）を市場との接触で検証する行為であり、文書生産ではない。

## 中間：パイロット価格テスト（During POC）

POC Step 1の対照実験と並行して、関心を示したインタビュー対象者のうち最低1件と、**有償パイロット契約**を締結する。

```text
パイロット契約の条件：
  - 期間：1〜3ヶ月
  - 金額：年間想定価格の20〜30%（パイロット割引）
  - 成果物：Thought Trace標準フォーマットでの評価レポート出力
  - 成功条件：パイロット終了時に本契約への移行判断ができること
```

「誰かが今日いくら払うか」のデータ点が1件でも存在することは、3セグメントの列挙より強力な市場シグナルである。

## 最低限の支払い意思証拠

POCのStep 1完了時点で、以下を最低限の支払い意思証拠として報告する。

```text
✓ 顧客発見インタビュー実施数（目標10〜15件、最低8件）
✓ 意向表明書（Letter of Intent）：最低3通
    - 内容：「POC結果が肯定的であれば、有償パイロットを検討する」旨の文書
    - 発行元：3セグメントから少なくとも各1通
✓ 有償パイロット契約：最低1件（実行中または締結済み）
```

## 評価軸との統合

支払い意思データは、**メタ評価**としてPOCの成功率と突き合わせる。

```text
検証すべき問い：
  - 評価overall ≥ 0.70 のタスクが多い条件は、実際に市場性（支払い意思）が高いか
  - 評価5軸のValue（価値）スコアと、実際の支払い意思額は相関するか
```

市場性（marketability）の評価は、設計者の自己評定ではなく、POC実行と並行して収集された実際の需要データで較正される。この較正がなければ、「Value 0.25」の重み付け（`03_コアコンポーネント/00_数値定義書.md` §2）は根拠のない仮定に留まる。

> 本節の内容はWisdom Council評価（v0.4-full）の推奨アクション3「支払い意思の実証を追加すること」に基づく。これは文書の追加ではなく、POCプロトコルへの計測項目の追加であり、「測ることに移る」ための前提整備である。

# 17. 最終定義

Insight Synapse First POCとは、

> AIが回答を生成するだけではなく、判断過程を記録し、評価し、その経験を次の判断改善へ利用できることを証明するための最小実験環境である。

このPOCの目的は、

「便利なAIを作ること」

ではない。

**成長する知能循環が本当に成立するかを検証すること。**
