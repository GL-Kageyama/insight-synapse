# Insight Synapse
## Human Interface Specification
### ヒューマンインターフェース仕様書 v0.1

---

# 1. 目的

本ドキュメントは、Insight Synapseにおける人間とAIの協調方法、操作方式、介入ポイントを定義する。

---

# 2. 基本思想

Insight Synapseでは、人間とAIの役割を分離する。

一般的なAI利用：

```text
人間

↓

指示

↓

AI

↓

回答
```

Insight Synapse：

```text
人間

↓

方向性・価値判断

↓

AI

↓

思考・制作・改善

↓

人間確認
```

---

# 3. 人間の役割

人間は作業者ではなく、

**目的・価値・方向性を調整する存在**

として扱う。

担当：

- Goal設定
- 制約設定
- 評価基準設定
- 最終判断
- 重要な方向修正

---

# 4. AIの役割

AIが担当すること：

- 情報整理
- 思考展開
- 仮説生成
- 制作
- 評価
- 改善提案

---

# 5. Human Intervention Point

人間が介入するポイントは限定する。

---

## Point 1
## Goal設定

開始時。

入力：

- 作りたいもの
- 達成したい目的
- 制約

例：

```yaml
goal:

objective:
"新しいAIサービスを設計する"

constraints:

- MVP優先
- 個人開発可能
```

---

## Point 2
## Direction確認

探索後。

確認：

- 方針
- 仮説
- 優先順位

---

## Point 3
## Evaluation確認

成果物後。

確認：

- AI評価
- 改善案
- 採用判断

# 13. 自律性レベル

Insight Synapseでは自律性を段階管理する。

---

## Level 0

質問回答。

---

## Level 1

提案型。

AIが案を出す。

---

## Level 2

半自律。

AIが実行し、人間確認。

---

## Level 3

監督型自律。

AIが進行、人間は重要判断。

---

## Level 4

高度自律。

限定領域で自己改善。

---

# 14. MVPの推奨レベル

最初：

```text
Level 2
```

理由：

- 制御可能
- 改善履歴が残る
- 暴走しにくい

# 16.5 進行状態の可視化とインサイト提示（構想）

> **【2026-08-08 追記：進行状態の可視化構想】**
> POC の対照実験（B0/B1/B2/C4 × N試行）を実行中、人間には「今何をやっているか」
> と「どのようなインサイトが得られたか」が見えないブラックボックスだった。
> 将来 UI で人間に「今の進行状況」と「得られた洞察」を伝えるために、
> 実行中に小さなログ（進捗・インサイト）を出力する構想を記す。

## 16.5.1 何を可視化するか

```text
「今、何をやっているか」（進行状況）
  - どの条件・どのタスクを実行中か
  - 現在のフェーズ（列挙 / 探索 / 生成 / 評価）
  - 試行の進捗（例: C4 12/20 試行目）

「どのようなインサイトが得られたか」（洞察）
  - 探索ループで未知がどれだけ減ったか（unknown_level の推移）
  - 新たに得られた作業仮説（hypotheses）
  - 評価スコアの傾向（条件間の比較）
```

## 16.5.2 最小実装（ログ出力）

実行中の各試行で、以下のような**一行ログ**を標準出力に出す（UI実装の前に利用できる）。

```text
[03/20] C4 dev-07 | explore | unknown_level 0.74→0.58 | 仮説+3件 | 評価 0.61
```

ログの要素:

| 要素 | 内容 |
|:---|:---|
| `[03/20]` | 試行の進行状況（全体の何番目か） |
| `C4` | 現在の条件 |
| `dev-07` | 現在のタスク |
| `explore` | 現在の判定（abstain / explore / create） |
| `unknown_level 0.74→0.58` | 探索ループによる未知の減少（インサイト） |
| `仮説+3件` | 探索で得られた作業仮説の数 |
| `評価 0.61` | その試行のブラインド評価スコア |

## 16.5.3 将来の UI での提示イメージ

```text
Web Dashboard での表示例:

┌─ 実行中 ────────────────────────────┐
│ [████████░░░░] C4 12/20            │  ← 進行状況
│ 現在: dev-07 を探索中               │
│ 未知レベル: 0.74 → 0.58（▼ 0.16）   │  ← 洞察
│ 作業仮説: +3 件                     │
└────────────────────────────────────┘
```

## 16.5.4 設計方針

- **ログは実行の副産物として出し、実行自体を阻害しない**（ベストエフォート）
- ログの構造は将来の UI 入力として使えるよう、機械可読（タブ区切り or JSON）と
  人間可読（説明文）の両方を持つ
- インサイトは「観測された事実」（unknown_level の推移・仮説数・評価スコア）に
  限定し、推測を混ぜない
- 実装箇所の候補: `poc/harness.py`（試行ループ）と `poc/conditions.py`（各条件の
  フェーズ遷移）にログ出力を追加する

# 18. 最終定義

Insight Synapse Human Interfaceとは、

> 人間が目的・価値判断・方向性を入力し、AIが思考・制作・評価・改善を実行するための協調インターフェースである。

MVPでは複雑なUIを作らず、Claude Code・Markdown・Gitによって、人間とAIの思考共有環境を構築する。
