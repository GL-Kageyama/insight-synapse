# Insight Synapse 資料ガイド

**Insight Synapse** の設計仕様書群（37本）をカテゴリ別に整理した資料です。

---

## この資料群は何を掴むためのものか

**Insight Synapse** は、「答えを生成するAI」ではなく、**「考え方を自ら改善し続けるAI」** を作るための**認知アーキテクチャフレームワーク**の設計です。

単に回答や成果物を出すだけでなく、AI自身の **思考状態・判断過程・評価・改善** を管理対象にします。思考を「目的に向かって状態を変化させる処理」と捉え、その**思考経路そのもの**を再利用可能な知識にしようとするのが全体の狙いです。

この資料群は、その構想（なぜ）→ 設計（どういう構造）→ 仕様（実装の詳細）→ 計画（いつ・どう作る）を順に追えるよう構成されています。

**最終定義（01 コンセプトと哲学に掲げる目標）**
> 「より速く答えるAI」ではなく、「考え方を自ら改善し続けるAI」を作ること。

---

## 核となる思想

この設計を貫く5つの考え方。

1. **思考 = 状態変化** — 思考は文章生成ではなく、状態を目的に近づける変換処理
2. **責務分離** — 判断 / 実行 / 記憶 / 評価 / 改善 をレイヤー分離
3. **思考の軌跡を中心とした記憶** — 「何を知っていたか」ではなく「どう考えたか」を保存
4. **評価は改善のため** — 採点が目的ではなく、次に改善すべき点を発見する
5. **人間は方向調整者** — 作業者ではなく、方向を調整する立場

主要コンポーネントは **State / Orchestrator / Skill / Primitive / Memory / Evaluation / Learning** の7つ。実行基盤は **Claude Code**（Markdown + Git + Skillシステム）を第一ターゲットとし、小さく検証しながら段階的に拡張していきます。

## 全体像と構成

システムの基本フローと、各カテゴリが対応するレイヤーの関係。

```
Goal
 ↓
Workflow Engine ──→ Orchestrator ──→ State管理 ──→ Skill / Primitive ──→ 実行
                                                                            ↓
                        Memory ←──── Learning ←──── Evaluation ←────────────┘
```

## 読み方の提案

- **全体像だけ掴みたい** → `01_コンセプトと哲学/01_AI思考アーキテクチャフレームワーク.md`（概要仕様書）を最初に。
- **設計を理解したい** → 02 アーキテクチャ → 03 コア → 04 スキル/ワークフロー → 05 メモリー → 06 評価/学習 の順。
- **実装を始めたい** → 11 実装計画（ロードマップ・最初の実装タスク・POC）→ 10 環境/リポジトリ → 08 技術仕様。
- **実装済みコードと照合したい** → 07 インターフェース・API、09 セキュリティを参照。
