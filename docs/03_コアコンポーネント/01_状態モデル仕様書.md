# Insight Synapse
## State Model Specification
### 状態モデル仕様書 v0.1

---

# 1. 目的

本ドキュメントは、Insight Synapseにおける「状態（State）」の定義、構造、更新ルールを定める。

Stateは単なる作業状況ではなく、

> AIが現在どのような認識状態にあり、次にどのような思考行動を取るべきかを判断するための内部状態

である。

---

# 2. Stateの基本概念

一般的なAI：

```text
入力
↓
回答
```

Insight Synapse：

```text
入力

↓

現在状態の形成

↓

状態変化

↓

次の状態

```

AIの活動は、

**State Transition（状態遷移）の連続**

として扱う。

---

# 3. State Object

基本構造：

```yaml
state:

  id:

  goal:

  context:

  phase:

  known:

  unknown:

  unknown_level:

  hypotheses:

  constraints:

  confidence:

  judgment:

  active_question:

  available_actions:

  history:

  timestamp:
```

> **正版**：`unknown` は未知項目のリスト（質的）、`unknown_level` は未知の度合い（0〜1、量的）。算出式は `03_コアコンポーネント/00_数値定義書.md` §3。`judgment` は棄権機構の記録（`normal` / `abstain`）。State 15フィールドのうち、unknown_levelはunknownから導出される量である。

# 4. 各項目定義

---

## 4.1 id

状態識別子。

目的：

- 状態履歴管理
- 差分比較

例：

```yaml
id:
state_0001
```

---

## 4.2 Goal

現在達成すべき目的。

例：

```yaml
goal:

objective:
"AI思考エンジンを設計する"

success_condition:

- 実装可能な構造
- 拡張可能性
```

---

## 4.3 Context

現在の背景情報。

含むもの：

- 関連情報
- 制約
- 前提条件

例：

```yaml
context:

project:
"Insight Synapse"

runtime:
"Claude Code"

stage:
"MVP"
```

---

## 4.4 Phase

現在の思考段階。

基本Phase：

```text
observe

↓

understand

↓

explore

↓

design

↓

create

↓

evaluate

↓

improve
```

> **Phase表記の正版**：`state.phase`（状態段階）は本書の7段階（小文字）を正版とする。これは実行手順の `workflow phase`（Observe→Question→Explore→Structure→Create→Evaluate→Reflect、大文字、`04_スキルとワークフロー/02_ワークフローシステム仕様書.md`）とは**別概念**である。
> - state.phase：AIが今どの思考段階にいるか（状態）
> - workflow phase：目的達成のためにどの処理をどの順で実行するか（手順）
>
> 混同を避けるため、Stateのphaseは小文字、Workflowのphaseは大文字で表記する。

---

例：

```yaml
phase:
design
```

---

## 4.5 Known

既知情報。

AIが確定事項として扱えるもの。

例：

```yaml
known:

- MemoryはMarkdown保存
- Claude Code利用
```

---

## 4.6 Unknown

未知情報。

非常に重要。

AIは未知を管理する。

例（機構的定義：各項目は重要度と解決状態を持つ）：

```yaml
unknown:

- item: "最適なAgent構成"
  importance: 0.9
  status: unresolved
- item: "Runtime方式"
  importance: 0.7
  status: partial
- item: "評価基準"
  importance: 0.5
  status: resolved
```

`status` は `unresolved`（未解決）/ `partial`（部分的解決）/ `resolved`（解決済み）の3値で、`unknown_level` の算出（重要度で重み付けした未解決項目の割合）に直接使われる。

> **表記の正版**：`unknown` は「何を知らないか」のリスト（質的）。未知の度合いを数値で表す場合は導出値 `unknown_level`（0〜1）を使う。unknown_level = 重要度で重み付けした未解決未知項目の割合（`03_コアコンポーネント/00_数値定義書.md` §3.2）。

## 4.8 Constraints

制約条件。

例：

```yaml

```

---

## 4.9 Confidence

現在状態への確信度。

0〜1で管理。

例：

```yaml
confidence:
0.65
```

用途：

- 探索継続判断
- 制作開始判断
- 棄権判断（下記）

### 棄権機構

不確実性が高い状態で「推測による判断」を下すことを防ぐため、以下の条件で判断を保留（棄権）する。

```text
棄権条件（いずれかを満たす場合、judgment = "abstain" を記録し判断を下さない）：

  - confidence < 0.3
  - unknown_level ≥ 0.7
```

棄権時は `reason`（保留理由）をStateに残し、代替案の検討・調査行動を優先する。数値の正版は `03_コアコンポーネント/00_数値定義書.md` §3.5。

# 6. State Machine

基本状態：

```text
                 Start

                   ↓

              Observe

                   ↓

             Understand

                   ↓

              Explore

              ↙     ↘

        Need More    Ready

            ↓          ↓

        Explore      Create

                       ↓

                  Evaluate

                       ↓

               Improve / Complete
```

### 棄権状態（Abstain）

`Ready` に見えても `confidence < 0.3` または `unknown_level ≥ 0.7` の場合は、`Create` へ進まず **Abstain（棄権）** に遷移する。

```text
Ready
  ↓（confidence が floor 未満）
Abstain → Explore（調査強化）→ Ready
```

棄権は「無回答」ではなく「保留理由を伴う判断停止」であり、Stateの `judgment = "abstain"` と `reason` に記録される。数値の正版は `03_コアコンポーネント/00_数値定義書.md` §3.5。

# 12. 設計上の重要原則

## 原則1

Stateを隠さない。

AIの現在状態は人間が確認可能にする。

---

## 原則2

Unknownを重要情報として扱う。

知らないことを管理する。

---

## 原則3

State変更には理由を残す。

---

## 原則4

不確実なときは判断を下さず、棄権する。

confidenceが低い状態で推測による判断を下さない。判断を保留して調査に回す。

---

# 13. 最終定義

Insight SynapseにおけるStateとは、

> AIが目的達成に向けて現在どの位置に存在し、何を理解し、何を知らず、次にどの行動を選択すべきかを表現する認知状態モデルである。

State ModelはInsight Synapse全体の判断基盤であり、Orchestrator・Memory・Evaluation・Learningを接続する中心レイヤーである。
