# 1. 目的

本ドキュメントは、Insight SynapseにおけるOrchestratorの役割、判断基準、思考コスト制御、実行フローを定義する。

目的：

> AIが単純に処理を実行するのではなく、状況を判断し、最適な思考経路を選択できるようにする。

---

# 2. Orchestratorの定義

Orchestratorとは、

> 目的達成のために、必要な思考・制作・評価プロセスを選択し制御するメタ判断エンジン

である。

一般的AI：

```text
入力
↓
生成
↓
出力
```

Insight Synapse：

```text
入力
↓
状況分析
↓
思考戦略選択
↓
Skill / Agent選択
↓
実行
↓
評価
↓
改善
```

---

# 3. Orchestratorの役割

## 3.1 Goal理解

目的を解析する。

確認：

- 本当の目的
- 制約
- 成功条件

## 3.2 State判断

現在位置を判断する。

管理：

- Phase
- Confidence
- Unknown
- Progress

## 3.3 Process選択

次の行動を決める。

選択：

- Explore
- Analyze
- Create
- Evaluate
- Reflect

## 3.4 Resource管理

利用する能力を決める。

対象：

- Skill
- Primitive
- Agent
- Tool

担当しないこと：

- 直接成果物を作る
- 詳細な分析を行う
- 長文生成を担当する

# 8. State Model

現在状態：

```yaml
state:
  goal: "新サービス設計"
  phase: "explore"
  confidence: 0.4
  unknown_level: 0.7
  risk: 0.5
  cost_level: medium
```

> **表記の正版**：`unknown` は未知項目のリスト（質的）、`unknown_level` は未知の度合い（0〜1、量的）。数値で未知度を表す場合は必ず `unknown_level` を使う。定義は `03_コアコンポーネント/00_数値定義書.md` §3。

# 10. Action選択基準

## 10.1 Explore判断

選択条件：

- Unknownが多い
- Confidenceが低い
- 判断材料不足

例：

```yaml
unknown_level: 0.8
confidence: 0.3
```

判断：

```text
Explore
```

（条件：unknown_level ≧ 0.6 で探索継続。`03_コアコンポーネント/00_数値定義書.md` §3.4）

## 10.2 Create判断

選択条件：

- Structure十分
- Goal明確
- Confidence十分

例：

```yaml
confidence: 0.85
structure: complete
```

判断：

```text
Create
```

## 10.3 Evaluate判断

選択条件：

- 成果物完成
- 判断結果確認が必要

## 10.4 Reflect判断

選択条件：

- 失敗
- 改善余地あり
- 新しいパターン発見

# 11. 思考コスト層

Insight Synapseでは、

「常に最大思考」

を避ける。

思考コスト：

```text
Level 0  Instant Response（即答）
↓
Level 1  Basic Reasoning（簡易分析）
↓
Level 2  Structured Thinking（構造化思考）
↓
Level 3  Deep Reasoning（深い探索）
↓
Level 4  Strategic Thinking（戦略思考・複数Agent検証を含む）
```

> **正版**：Level名・対応する処理の正版は `03_コアコンポーネント/04_思考コスト管理仕様書.md`。Level 4の「複数Agent検証」はStrategic Thinkingの一部として扱う。

## Cost Level例

### Level 0

対象：

- 単純変換
- 定型処理

例：

文章修正。

### Level 1

対象：

- 簡単な生成
- 軽い分析

### Level 2

対象：

- 企画
- 設計
- 問題整理

### Level 3

対象：

- 新規事業
- 研究
- 複雑問題

### Level 4

対象：

- 重要意思決定
- 長期影響
- 複数評価必要

# 12. 思考コスト判断基準

判断式：

```text
Thinking Cost = Importance × Uncertainty × Impact
```

- Importance：重要度（0〜1）
- Uncertainty：不確実性（Stateの `unknown_level` と一致）
- Impact：影響範囲（0〜1）

> **正版**：Cost式・思考Level定義の正版は `03_コアコンポーネント/00_数値定義書.md` と `03_コアコンポーネント/04_思考コスト管理仕様書.md`。しきい値は Cost < 0.3 → Level 0-1 / 0.3 ≦ Cost < 0.7 → Level 2 / Cost ≧ 0.7 → Level 3-4。

例：

簡単な文章修正：

```text
Level 1
```

新規事業設計：

```text
Level 3〜4
```

# 19. Policy Layer

判断基準は固定ではなくPolicyとして管理する。

場所：

```text
core/orchestrator/policy.yaml
```

例：

```yaml
policy:
  exploration:
    when_unknown: high
  creation:
    minimum_confidence: 0.75
  evaluation:
    always_after_creation: true
```

---

# 20. Alternative Analysis

重要な判断では複数候補を比較する。

例：

```markdown
候補A: Create
  メリット: 速度
  リスク: 品質不足
候補B: Explore
  メリット: 精度向上
  リスク: 時間増加
選択: Explore
  理由: 初期設計段階のため
```

---

# 25. Orchestratorが避けること

## 1

すぐ制作する。

理由：

探索不足。

## 2

全部Agent化する。

理由：

コスト増大。

## 3

評価なしで終了する。

理由：

改善不能。

# 29. 最終定義

Insight Synapse Orchestratorとは、

> AIが「何をするか」ではなく、「なぜそれをするべきか」「どの程度考えるべきか」「どの能力を使うべきか」を判断するためのメタ認知制御層である。

Insight Synapseの知能の中心は生成能力ではなく、

**思考方法を選択する能力**

にある。
