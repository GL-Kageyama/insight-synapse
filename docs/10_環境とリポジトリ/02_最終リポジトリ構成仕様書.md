# 4. 各Layerの責務

## core/

Insight Synapseの中枢。

担当：

- 状態管理
- 判断
- 制御

## core/schemas/

**コア抽象層**（Runtime非依存）。Insight Synapseの思考資産を特定Runtimeから独立させる。

担当：

- State Schema（現在状態の構造定義）
- Trace Schema（Thought Traceの標準交換フォーマット）
- Evaluation Schema（評価5軸・算出式）

コア抽象はClaude Code等の実行基盤に依存しない。蓄積した思考資産はRuntimeが変わっても読み替え可能な標準フォーマットで保存される。

---

## adapters/

**アダプタ層**。コア抽象と特定Runtimeの変換を担う。

担当：

- `claude-code/`：第一アダプタ。コア抽象を Markdown + YAML + Git + Skill にマッピング
- 将来：API Server / IDEプラグイン / Web UI

依存方向は「アダプタ → コア抽象」のみ。コア抽象はアダプタの詳細を知らない。

---

## orchestrator/

最重要。

担当：

- 次Action判断
- Skill選択
- Agent呼出判断

---

## workflows/

目的達成までの流れ。

例：

```text
Creation

Research

Problem Solving
```

---

## skills/

再利用可能な能力。

例：

```text
Analyze

Create

Critique
```

---

## primitives/

最小思考操作。

例：

```text
分解

比較

抽象化
```

---

## agents/

専門判断主体。

例：

```text
Logic Evaluator

Creative Evaluator
```

# 15. 最終定義

Insight Synapse Repositoryとは、

> AIを単なる生成ツールとして実装するのではなく、思考・判断・制作・評価・改善を循環させる知的アーキテクチャとして管理するための開発基盤である。

このリポジトリの中心はコードではない。

中心にあるものは、

**AIが成長するための構造設計**

である。
