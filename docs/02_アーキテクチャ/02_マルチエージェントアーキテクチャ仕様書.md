# Insight Synapse
## Multi Agent Architecture Specification
### マルチエージェントアーキテクチャ仕様書 v0.1

---

# 1. 目的

本ドキュメントは、Insight Synapseにおけるマルチエージェント利用方針、役割分担、協調方法を定義する。

目的：

> AIを大量配置するのではなく、必要な場所に専門的な視点を追加することで、判断品質と制作品質を向上させる。

---

# 2. 基本思想

Insight Synapseでは、

「全部をマルチエージェント化する」

ことを目的にしない。

---

悪い構造：

```text id="0x1d0m"
Agent A

Agent B

Agent C

↓

全員で制作
```

問題：

- 思考重複
- コスト増加
- 責任不明
- 方向性の分散

---

良い構造：

```text id="9w4m1k"
Orchestrator

↓

必要なAgentだけ呼ぶ

↓

統合判断
```

---

# 4. Orchestratorの役割

Orchestratorは司令塔。

担当：

- Agent利用判断
- Task分割
- 結果統合
- 思考コスト管理
- 優先順位決定

---

判断基準：

```text id="x2n3q6"
Task Complexity

+

Uncertainty

+

Need for Multiple Perspectives

+

Cost
```

---

# 5. 制作におけるAgent設計

## 原則

制作工程では、基本的に単一のCreatorを中心にする。

理由：

制作には、

- 一貫性
- 文脈維持
- 世界観維持

が重要だから。

---

構造：

```text id="q2n5w7"
Orchestrator

↓

Creator Agent

↓

Artifact
```

---

# 6. 制作時にAgentを追加する場合

必要な場合だけ呼ぶ。

例：

## Research Agent

役割：

情報探索。

---

## Critic Agent

役割：

弱点発見。

---

## Specialist Agent

役割：

専門知識補完。

---

構造：

```text id="r8m3k2"
Creator

↓

必要時

├── Research Agent

├── Specialist Agent

└── Critic Agent

↓

Creator統合
```

---

# 7. 評価におけるAgent設計

評価はマルチエージェントが適している。

理由：

価値判断は単一視点では偏る。

---

構造：

```text id="m9x4p1"
Artifact

↓

Evaluation Orchestrator

↓

┌──────────────┐
│ Quality Agent │
├──────────────┤
│ Logic Agent   │
├──────────────┤
│ Creative Agent│
├──────────────┤
│ Risk Agent    │
└──────────────┘

↓

統合評価
```

# 9. Agent Communication

Agent同士は直接議論させすぎない。

推奨：

```text id="9c7n4d"
Agent

↓

Structured Report

↓

Orchestrator

↓

Decision
```

---

理由：

自由会話は、

- 情報量増大
- 収束困難

になるため。

# 18. 最終定義

Insight Synapse Multi Agent Architectureとは、

> 多数のAIを並列配置する仕組みではなく、単一の統合判断層（Orchestrator）の下で、必要な専門的視点だけを動的に呼び出し、品質と改善能力を高める協調知能アーキテクチャである。

設計思想：

**制作は集中、評価は分散、判断は統合**

である。
