# Insight Synapse
## Workflow Engine Architecture Specification
### ワークフローエンジンアーキテクチャ仕様書 v0.1

---

# 1. 目的

本ドキュメントは、Insight SynapseにおけるWorkflow Engineの役割、構造、実行方式を定義する。

目的：

> AIが固定された手順を実行するのではなく、状況に応じて最適な思考・制作プロセスを選択できる仕組みを構築する。

---

# 2. Workflowの定義

Insight SynapseにおけるWorkflowとは、

> 目的達成までの思考・制作・評価プロセスを管理する動的な実行計画

である。

---

一般的Workflow：

```text
Step 1

↓

Step 2

↓

Step 3
```

---

Insight Synapse Workflow：

```text
Goal

↓

State Analysis

↓

Next Action Decision

↓

Process Selection

↓

Execution

↓

Evaluation

↓

Adjustment
```

---

# 3. Workflowの役割

Workflow Engineは以下を担当する。

## 3.1 Phase管理

現在の段階を管理。

例：

```text

↓

Structure

↓

Create

↓

Evaluate

↓

Improve
```

---

## 3.2 Process制御

次の処理を決定する。

---

## 3.3 Feedback反映

評価結果によって流れを変更する。

# 6. State Driven Workflow

Insight Synapseでは状態によって流れを変える。

例：

```yaml
state:

unknown:
0.8

confidence:
0.3
```

判断：

```text
Explore Phase継続
```

---

別状態：

```yaml
unknown:
0.1

confidence:
0.9
```

判断：

```text
Create Phaseへ移行
```

# 9. Transition条件

Phase移動条件を定義する。

例：

```yaml
transition:

from:
explore

to:
create

condition:

confidence >= 0.75

unknown_level <= 0.25
```

> **正版**：制作開始（Create）判断のしきい値は `confidence ≧ 0.75 かつ unknown_level ≦ 0.25`（`03_コアコンポーネント/00_数値定義書.md` §3.4）。旧記述の `confidence > 0.8` は同判断の例示であり、正版のしきい値に揃えた。

# 15. Workflow YAML設計例

```yaml
workflow:

name:
creation

phases:

- research

- structure

- create

- evaluate


transition:

evaluate:

if:
score < 0.7

next:
improve
```

> **正版**：評価スコアは0〜1スケールに一本化（`03_コアコンポーネント/00_数値定義書.md` §2）。合格しきい値は overall ≧ 0.70（Pass）/ 0.50〜0.69（Revise）/ < 0.50（Regenerate）。上記の `score < 0.7` は「合格に満たない → improve」を意味する。

# 20. 最終定義

Insight Synapse Workflow Engineとは、

> AIの目的達成までの思考・制作・評価プロセスを管理し、状態に応じて最適な経路へ変化する動的実行制御システムである。

Workflowとは単なる手順ではない。

**AIが状況に応じて考え方を変えるための思考経路設計である。**
